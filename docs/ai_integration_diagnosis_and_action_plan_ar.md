# تشخيص دمج الذكاء الاصطناعي وخطة المعالجة

**المشروع:** ERP Aluminum & Glass  
**تاريخ المراجعة:** 17 أكتوبر 2026  
**نوع المراجعة:** تدقيق ساكن لمسارات الذكاء الاصطناعي في تطبيق Flutter  

## 1. الخلاصة التنفيذية

الدمج الحالي يصلح كنموذج أولي، لكنه غير آمن للنشر الإنتاجي بصورته الحالية. المشكلة الأساسية ليست جودة إجابات Gemini فقط؛ بل أن التطبيق يسمح لمخرجات احتمالية وغير موثوقة بإنشاء زبائن وطلبيات وقراءة بيانات مالية ومخزون دون طبقة تحقق وصلاحيات وتأكيد موحدة.

### التقييم

| المجال | التقييم | الملاحظة |
|---|---:|---|
| العرض التجريبي | 5/10 | الوظائف ظاهرة وتغطي النص والصوت والصور والفواتير |
| الجاهزية للإنتاج | 2/10 | توجد مخاطر مباشرة على البيانات والعمليات |
| الأمن والخصوصية | 1/10 | مفتاح مكشوف وتخزين غير آمن وصلاحيات غير مطبقة |
| سلامة البيانات | 1/10 | كتابة مباشرة وقيم افتراضية وغياب المعاملات |
| الاختبارات والمراقبة | 0/10 | لا توجد اختبارات AI أو قياس تكلفة وجودة |

**قرار النشر:** يجب عدم تشغيل أو نشر الأوامر التي تعدل قاعدة البيانات قبل إنجاز عناصر P0 الواردة في هذه الخطة.

## 2. النطاق والحدود

شملت المراجعة الخدمات والشاشات والإعدادات المرتبطة بـGemini، والمساعد النصي والصوتي، وتحليل المخططات، وماسح الفواتير، ومسارات التنقل والحفظ.

هذا التشخيص عالي الثقة على مستوى الكود، لكنه لا يمثل اختبار اختراق كاملًا ولا تدقيقًا لحركة الإنتاج أو لوحة Google Cloud. الوصول إلى يقين مطلق يتطلب أيضًا اختبارًا ديناميكيًا، وحسابات متعددة الصلاحيات، ومراجعة سجل الشبكة والمزود.

## 3. المخاطر الحرجة

### 3.1 مفتاح Gemini مكشوف ومخزن بطريقة غير آمنة

- توجد قيمة تشبه مفتاحًا حقيقيًا داخل `lib/settings/app_settings.dart`.
- أي مفتاح كان موجودًا في المصدر أو Git أو نسخة APK/EXE يجب اعتباره مكشوفًا.
- مفتاح المستخدم يحفظ كنص عادي في `SharedPreferences`.
- حقل المفتاح في الإعدادات غير مخفي ويحفظ القيمة أثناء الكتابة.
- لا يوجد عزل واضح للمفتاح بين المستخدمين الذين يستعملون الجهاز نفسه.

**القرار:** إلغاء المفتاح المكشوف فورًا، إنشاء مفتاح جديد، وتنظيفه من تاريخ Git وملفات البناء. لا يكفي حذف السطر في commit جديد.

### 3.2 اتصال مباشر من تطبيق العميل إلى Gemini

الاتصال يتم من Flutter مباشرة باستعمال `x-goog-api-key`. لذلك لا توجد طبقة مركزية تفرض الهوية والصلاحيات والميزانية ومعدل الاستخدام والتسجيل التدقيقي وتعطيل الميزة.

**القرار:** استخدام Backend/Proxy مصادق عليه. إذا تقرر اعتماد BYOK، فيجب استعمال مخزن أسرار آمن مع عزل الحسابات وتحذير الخصوصية.

### 3.3 تنفيذ عمليات كتابة دون تأكيد

يمكن للمساعد تنفيذ `create_order` و`create_client` مباشرة بعد قراءة `action_type` من رد النموذج. صورة المخطط يمكنها كذلك إنشاء طلبية مباشرة.

لا توجد شاشة مراجعة، أو تأكيد صريح، أو صلاحية مستقلة، أو زر تراجع، أو مفتاح منع التكرار، أو سجل تدقيقي كامل.

**القرار:** يمنع النموذج من الكتابة المباشرة. ينتج Draft فقط، ثم يمر عبر التحقق وعرض المراجعة والتأكيد قبل الحفظ.

### 3.4 إنشاء طلبيات ناقصة أو خاطئة

عند غياب البيانات، يختار المسار الحالي قيمًا مثل زبون جديد وأبعاد 1000 × 1000 ونظام French وزجاج Simple وسعر صفر. كما ينشئ زبونًا جديدًا دائمًا ويحفظ التقسيمات فارغة.

هذا قد ينتج زبائن مكررين وطلبيات وهمية، ولا يمر بمحرك إنشاء الطلبية والتسعير والكتالوج المستخدم في بقية التطبيق.

**القرار:** لا قيمة افتراضية للحقول التجارية الحرجة. البيانات الناقصة تعني سؤال توضيح أو رفض الحفظ.

### 3.5 غياب معاملات قاعدة البيانات

إنشاء الزبون والطلبية والتفاصيل يتم عبر عمليات منفصلة. حفظ الفاتورة كذلك ينسخ الصورة وينشئ المقاطع والفاتورة والعناصر تدريجيًا. فشل خطوة وسطية يترك بيانات جزئية.

**القرار:** تنفيذ كل عملية تجارية مركبة داخل transaction واحدة مع rollback وتنظيف الملفات عند الفشل.

### 3.6 تجاوز الصلاحيات

التنقل الناتج عن AI لا يطبق دائمًا فحوص `canAccess...` الموجودة في الواجهة. كما لا تتحقق خدمات AI من صلاحية قراءة الديون والصندوق والمخزون أو إنشاء الزبائن والطلبيات.

**القرار:** كل Tool يجب أن يطلب Permission محددة على الخادم وداخل التطبيق، بصرف النظر عن ظهور الزر في الواجهة.

## 4. دقة وسلامة الوظائف

### 4.1 الحماية الهندسية الحالية ليست محرك سلامة

الحماية الحالية تتكون أساسًا من شرطين مرتبطين بارتفاع الزجاج وعرض النظام. لا تراعي وزن الزجاج أو الضلفة أو البروفيل أو التدعيم أو المفصلات أو الرياح أو قواعد المصنع.

**الخطر:** منح المستخدم ثقة زائفة بأن الطلبية اجتازت فحصًا هندسيًا.

**القرار:** تكون القواعد الهندسية حتمية ومأخوذة من الكتالوج والمواصفات. دور AI هو الشرح فقط، وليس اختراع قرار السلامة.

### 4.2 عقد JSON غير صارم

- استخدام JSON MIME دون `responseSchema` أو Function Calling حقيقية.
- `action_type` يقبل أي نص.
- المعاملات غير Typed ولا تخضع لحدود أو حقول إلزامية.
- فشل JSON يعالج أحيانًا بـRegex أو نص بديل قد يوحي بالنجاح.
- الأنواع النصية للأرقام قد تسبب runtime error.

**القرار:** تعريف أدوات ذات schemas وإجراء validation مستقل قبل أي تنفيذ.

### 4.3 ملخص الصندوق غير موثوق

التصنيف يعتمد على كلمات داخل النوع والوصف واسم الصندوق، ويعتبر العمليات غير المعروفة مصروفات ويضع غير المصنف في الورشة. هذا لا يغطي المرتجعات والتحويلات والإلغاءات وحالات الدفع والرصيد الافتتاحي.

**القرار:** استعمال نفس خدمة التقرير المالي الرسمية في التطبيق. يجب ألا ينفذ AI حسابًا موازيًا.

### 4.4 فحص المخزون سطحي

الفحص يقرأ المخزون ويستعمل تطابقًا جزئيًا ثم يأخذ أول نتيجة. لا يفرق بدقة بين الكود واللون والوحدة والموقع والمتاح والمحجوز.

**القرار:** أداة بحث منظمة تعيد النتائج المتعددة ومعرفاتها وكمياتها المتاحة والمحجوزة، ثم يختار المستخدم عند الالتباس.

### 4.5 البحث عن الزبائن يعرض بيانات حساسة

البحث يأخذ أول تطابق جزئي وقد يعرض الهاتف والدين دون فحص صلاحية أو معالجة تشابه الأسماء.

**القرار:** فرض صلاحية قراءة البيانات المالية، وإرجاع قائمة اختيار عند تعدد النتائج، وقراءة الدين من المصدر المحاسبي الرسمي.

### 4.6 تحليل المخططات غير مكتمل

عند وجود عدة نوافذ، يضع prompt النافذة الأولى في الحقول الرئيسية والبقية في الملاحظات، ثم قد ينشئ طلبية مباشرة. كما أن التقسيمات المستخرجة لا تنتقل إلى سجل الطلبية الحالي.

**القرار:** إخراج قائمة نوافذ Typed، وعرض كل نافذة وتقسيماتها وثقتها، وعدم الحفظ قبل مراجعة المستخدم.

### 4.7 ماسح الفواتير يحتاج تحققًا محاسبيًا

النقطة الإيجابية أنه يبقي العناصر غير المطابقة للمراجعة، لكن لا يوجد:

- تحقق من مجموع الكميات والأسعار مقابل الإجمالي.
- كشف فاتورة مكررة.
- تحقق من المورد والتاريخ والعملة والضرائب والخصم.
- منع القيم السالبة أو غير المنطقية.
- transaction موحدة للحفظ.

درجة `confidence` الحالية تقدير من النموذج وليست مقياس OCR معايرًا.

## 5. الخصوصية والوسائط

### 5.1 الصوت

- Windows يرفع التسجيل الكامل إلى Gemini، بينما منصات أخرى قد ترسل النص فقط.
- لا توجد موافقة واضحة على مغادرة الصوت للجهاز.
- لا توجد سياسة حذف واحتفاظ ظاهرة.
- الملفات المؤقتة لا تنظف بوضوح بعد المعالجة.
- لا يوجد حد قوي لحجم تسجيل fallback أو إلغاء لعملية الرفع.

### 5.2 الصور والفواتير

- لا يوجد حد للحجم أو الدقة.
- لا يوجد ضغط أو إزالة EXIF.
- MIME يحدد غالبًا من الامتداد وليس من محتوى الملف.
- صور الفواتير تحفظ محليًا دون تشفير أو سياسة احتفاظ.

**القرار:** موافقة صريحة، وقيود حجم، وضغط، وإزالة metadata، وحذف الملفات المؤقتة، وسياسة خصوصية واحتفاظ واضحة.

## 6. الاعتمادية والتكلفة

- fallback يجرب نموذجين بمهلة 25 ثانية لكل نموذج، ما قد يرفع الانتظار إلى نحو 50 ثانية.
- قد يعيد المحاولة حتى في أخطاء المفتاح أو الطلب غير الصالح.
- لا يوجد exponential backoff أو jitter أو احترام `Retry-After`.
- لا يوجد إلغاء أو circuit breaker أو feature kill switch.
- لا يتم تسجيل عدد tokens أو التكلفة أو زمن الاستجابة أو request ID.
- يعاد إرسال system prompt وسجل المحادثة في كل مرة.
- لا يوجد cache أو توجيه محلي للأوامر البسيطة.

## 7. التسجيل والأخطاء

- قد يطبع التطبيق جسم رد Gemini الكامل في `debugPrint`.
- قد يحتوي السجل على أسماء وهواتف وديون ومحتوى فاتورة أو مخطط.
- بعض Exceptions الداخلية تعرض للمستخدم مباشرة.

**القرار:** Redaction مركزي، ورسائل عامة للمستخدم، وسجلات منظمة لا تحتوي أسرارًا أو بيانات شخصية، مع معرف تتبع بدل جسم الطلب.

## 8. المكتبات والصيانة

- `google_generative_ai: ^0.4.7` غير مُصانة حاليًا حسب Google، والتوصية الرسمية لFlutter هي Genkit Dart أو Firebase AI Logic.
- `http: any` غير مثبت الإصدار، ما يضعف قابلية إعادة بناء النسخة.
- توجد خدمة قديمة مكررة `ai_voice_service.dart` لا يظهر أنها مستخدمة، وتزيد سطح الصيانة والخطر.
- أسماء `gemini-3.8-flash` و`gemini-3.6-flash` صحيحة حاليًا؛ المشكلة ليست أسماء النماذج بل البنية المحيطة بها.

## 9. الاختبارات المفقودة

لا توجد اختبارات مخصصة تغطي:

- parsing وعقد JSON.
- الأنواع الخاطئة والحقول الناقصة.
- الصلاحيات.
- التأكيد قبل الكتابة.
- منع التكرار.
- rollback عند فشل منتصف العملية.
- prompt injection من النص والصوت والصورة.
- تطابق الفاتورة والإجمالي.
- الشبكة والمهلة والـquota والمفتاح غير الصالح.
- تعدد اللغات والمنصات.
- الملفات الكبيرة وتنظيف الملفات المؤقتة.

## 11. المعمارية المستهدفة

```text
المستخدم
  -> واجهة النص/الصوت/الصورة
  -> تنقية البيانات + موافقة الخصوصية
  -> Backend مصادق عليه
  -> نموذج Gemini يستخرج Intent/Draft فقط
  -> JSON Schema + Validation
  -> فحص صلاحيات المستخدم
  -> محرك قواعد التطبيق الرسمي
  -> Preview للمستخدم
  -> تأكيد صريح
  -> Transaction + Idempotency
  -> Audit log + Metrics
```

النموذج لا يتصل بقاعدة البيانات ولا يقرر السلامة أو السعر أو الرصيد. الأدوات الحتمية في التطبيق أو الخادم هي مصدر الحقيقة.

## 12. الاختبارات الإلزامية قبل الإطلاق

1. محاولة مستخدم عامل فتح الصندوق عبر AI.
2. طلب إنشاء طلبية دون اسم أو أبعاد.
3. إعادة إرسال الطلب نفسه بعد timeout.
4. إرجاع Gemini رقمًا كنص وقيمة سالبة وقيمة ضخمة.
5. Prompt injection داخل صورة مخطط وفاتورة.
6. فشل قاعدة البيانات بعد إنشاء الزبون وقبل تفاصيل الطلبية.
7. فاتورة مكررة ومجموع عناصر لا يساوي الإجمالي.
8. تسجيل صوتي كبير وإلغاء المستخدم أثناء الرفع.
9. تبديل حسابين على الجهاز نفسه والتحقق من عزل المفتاح والسجل.
10. انقطاع الشبكة و429 و401 و500 مع قياس زمن الاستجابة.
11. تطابق عدة زبائن أو مواد بنفس الاسم.
12. التحقق من خلو logs وCrash reports من البيانات الحساسة.

## 13. تعريف الجاهزية للإنتاج

لا تعد الميزة جاهزة حتى تتحقق الشروط التالية معًا:

- لا أسرار داخل العميل أو Git.
- لا كتابة دون صلاحية وPreview وتأكيد.
- كل عملية مركبة ذرية وقابلة للتراجع.
- الحساب المالي والهندسي يأتي من مصدر رسمي حتمي.
- كل Tool لها schema واختبارات وصلاحيات.
- توجد مراقبة تكلفة وأخطاء وزمن استجابة.
- توجد سياسة خصوصية وموافقة للوسائط.
- تنجح اختبارات injection والتكرار وفشل منتصف العملية.

## 14. القرار النهائي

المساعد الحالي يجب اعتباره **واجهة تجريبية لفهم النص والصوت والصور**، لا وكيلًا مخولًا بتنفيذ العمليات. أكبر إصلاح مطلوب هو تغيير مبدأ الدمج من:

> النموذج يفهم ثم ينفذ مباشرة.

إلى:

> النموذج يقترح مسودة، والنظام يتحقق، والمستخدم يؤكد، والأدوات الحتمية تنفذ.

بعد إنجاز P0 يمكن بدء اختبار محدود داخلي. وبعد P1 والاختبارات الإلزامية يمكن التفكير في Beta مراقبة. أما النشر العام قبل ذلك فيعرض بيانات الزبائن والطلبيات والحسابات لمخاطر غير مقبولة.
